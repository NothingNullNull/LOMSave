# LOMSave 2.0 自动检查

在仓库根目录执行，将占位符替换为实际游戏安装目录：

```powershell
python -m pip install -r .\tools\requirements.txt
$gameDir = '<游戏安装目录的完整路径>'
.\tests\Run-Tests.ps1 -GameDir $gameDir -BepInExVersion 5
.\tests\Run-Tests.ps1 -GameDir $gameDir -BepInExVersion 6 -BepInExDir '<BepInEx 6 core 目录>'
```

`-Python` 可指定 Python 可执行文件。需要 .NET SDK、本地游戏程序集和对应的 BepInEx 5.4.23.5 或 6.0.0-be.692 Unity Mono（当前为 x64）；测试构建始终禁用自动部署，不读取或修改玩家存档。

缺少剧情资料时，入口脚本从本地游戏提取 `back_02_501`、`ch2_4_5_3` 到 `assets/story/`，不分发游戏脚本。游戏更新后可手动重新提取：

```powershell
$gameDir = '<游戏安装目录的完整路径>'
python .\tools\Extract-TestStories.py --game-dir $gameDir
```

2.0.5 当前离线基线为两种构建各 79 项通过、44 个补丁方法目标及参数检查，使用游戏 `release_1.0.6000.3`。两种构建分别核对加载器依赖，序列化程序集身份均保持 `LOMSave2, Version=0.0.0.0`。测试入口会输出本次测试资料与 `results.txt` 的位置。

## 覆盖范围

- 原生存档与附加档配对、原子替换、覆盖清理和写入失败处理。
- 旧格式反序列化、格式 2 回退、格式 3 无验证快照读取、格式 4 命运事件，以及格式 5 原生判定与等待事件。
- Lua 跨脚本标量变量、脚本内自动存档边界、读取入口隔离和等待位置。
- `Position`、`Switch`、`Condition` 的记录结果、事件顺序和原生存档哈希配对；格式 3/4 缺少判定时按当前位置补录，保留后续台词。检查 `Position` 不重复记录，以及 `Switch`、`Condition` 保留原生调用的补丁约束和返回结果覆盖。
- 判定类型/名称、台词 hash、事件类型和选项范围错位时同步抛错；真实 MoonSharp 协程在错误后不执行后续命令。无效判定和原生档哈希不匹配时拒绝附加档，原有文件保持不变。
- 最外层已完成 `WaitEvent` 的格式 5 序列化、重演时跳过延迟、等待错位停止；旧档补录缺少的等待，子剧情入口保留回放直到判定补齐。用真实 MoonSharp 挂起验证目标等待前不执行后续奖励，等待恢复后才记录完成；连续多个等待后仍到达正确的对话位置。
- 台词或选项内部的嵌套等待由外层事件覆盖，避免在 `SayEvent` 前误插 `WaitEvent`。关闭 `Replay.FastPresentation` 时，资源和黑幕过渡保留原迭代器，探测不调用 `MoveNext`。
- 旧厨房子剧情只在目标边界及准确 Lua 文件名上补资源，每次读取仅注入一次；重试、重置及零事件读取保持正确行为。
- MoonSharp 合成异步加载环境真实挂起及恢复 `runwait`：背景、两个人物逐一完成加载后才显示立绘并执行子剧情，检查背景、标题、表情、站位与朝向，以及父剧情数值不变；用例不包含游戏脚本。
- 回放日志回调仅排队、筛选及保留首个异常，回调返回前不改变回放、加载或提示状态；重试清除待处理异常。
- 恢复状态下 Harmony 存档后置处理立即退出，原生档和附加档字节保持不变，也不继续读取场景或处理附加档。
- 原生读取恢复存档起点，不沿用上一会话值，也不改写非回放路径的运行剧情；空起点值按原值恢复。
- 状态快照独立性、差异定位、集合顺序与时间戳、报告和异常回放判定。
- 排除主档/嵌入还原存档的 `FreeRandomState`，保留同名 Lua 变量与事件标记差异；0/1/2 项有效差异的报告与玩家警告阈值。
- 命运属性/好感/标记、扣点与撤销、多个面板和起始状态校验。
- Harmony 目标方法和注入参数与本地游戏程序集匹配。
- 游戏、Unity、Mono 与 Doorstop 加载器位数匹配；人物介绍仅展示模式不激活关系。

历史格式测试使用 `fixtures/format2/LOMSave2.dll` 和 `fixtures/format3/LOMSave2.dll`，在独立进程中生成合成测试档；这些 DLL 是历史 MOD 构建产物，不是游戏程序集，也不应安装到游戏。

## 发布包检查

执行 `tools/Build-Release.ps1` 时自动检查 5/6 两套普通包与一键包内 DLL、整合包根目录结构、官方 BepInEx 全部文件、第三方许可与源码及发布校验文件；失败会阻止发布。

```powershell
python .\tools\package_bundle.py verify --release-dir .\dist --version 2.0.5
python .\tests\test_release_package.py --release-dir .\dist --version 2.0.5
```

将版本号替换为本次发布版本。发布包测试在项目 `.work/` 内模拟解压覆盖，确认已有配置、其他插件和存档标记保持原样；同时检查缺包、缺少校验项、错误组件、重复 MOD、个人文件和多余外层目录会被拒绝。共 22 项，包含缺少整套构建、两种 DLL 相同、错用另一套加载器的拒绝检查。此检查不代替实际游戏启动验证。

## 限制

独立 CLR 无法执行 Unity 内部 ECall，测试中的引擎交互使用替身，不能证明实际 Harmony 安装、场景生命周期、输入或界面正常。MoonSharp 初始化时可能输出 UnityAssetsScriptLoader 的 SecurityException；最终以各项结果和退出码判断，不能把该信息当成游戏实机日志。

目标等待的离线流程使用生产代码的脚本/时长匹配条件，替代 `EndReplay` 的引擎操作，再让真实 Lua 等待协程挂起；该测试证明后续剧情不会越过挂起点，不单独证明 Unity 时间倍率、输入恢复和画面状态。缓存命中与立即完成黑幕的开启路径由下述隔离实机回归检查。旧格式在同一脚本内出现多次等时等待时可能缺少唯一定位信息，无法保证所有历史等待存档都能精确还原。

`ch2_4_5_3` 边界用例截取至 `D_2_4_5_3_001` 对话，检查两句对话、自动存档、选择和分支对话的顺序。更新脚本后若结构改变，应重新核对有效边界，不能直接放宽断言或把用例失效当成游戏兼容性结论。

实机检查见 [游戏更新兼容性检查清单](../游戏更新兼容性检查清单.md)。`FreeRandomState` 不计入差异，原值仍保留在完整报告并标记为已忽略。
