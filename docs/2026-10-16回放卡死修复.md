# 子剧情回放停在 0/3 的修复与验证

环境：游戏 `release_1.0.6000.2`（Steam Build `25957922`）、Unity `2020.3.49f1`、BepInEx `5.4.23.5` Windows x64 Mono。

## 触发与原因

在厨房剧情的子脚本 `S8300_01_01` 完成前三句对话后保存，再通过 F9 读取。回放停在 `0/3`，原生日志记录 `CharacterPlaceholder.LoadCharacterPortrait` 的 `KeyNotFoundException`。

父脚本 `S8300_01` 加载视图与人物后，通过 `SetNextScript` 和 `Init` 沿用同一个 `LuaManager`、解释器及场景进入子脚本。原补丁在每次 `ExecuteLuaScript` 时重新捕获边界并清空事件，导致读档直接从依赖父场景资源的子脚本执行。新场景的人物字典为空，Lua 协程在消费第一个事件之前终止，模组仍保持回放和输入锁。

## 修复

同一 `LuaManager` 内保留首次剧情入口和完整事件历史；新实例才建立新边界。读档首次执行时认领新实例，后续子脚本继续沿用原边界；完整重置和新读取清理旧实例关联。

对已生成的 `S8300_01_01` 旧档，在原 Lua 协程中插入纯视觉初始化，使用 `runwait` 完整等待背景和人物资源，然后恢复人物站位与朝向。前置不重放父剧情中的选择、骰子、奖励或属性修改。兼容处理按已知边界识别，不依赖旧格式号，因此旧边界再次保存后仍能读取。其他历史子脚本没有增加推测性的预置初始化。

运行异常先记录到回放保护器，在下一帧主线程处理：停止剧情协程、解除遮罩和输入锁、恢复速度、保留失败报告并要求重新读取。恢复要求解除前阻止手动、自动、全局和附加档写入。F9 重新读取会重置失败状态。逐事件日志保留进度和当前脚本，方便定位后续故障。

`Replay.NoProgressTimeoutSeconds` 默认 45 秒，可设为不大于零以关闭。计时使用真实时间，排除加载、战斗和需要玩家操作的暂停，以及明显的应用挂起或阻塞帧。

## 本地实机验证

测试使用完整存档副本；所有存档路径重定向到独立目录，临时阻止设置和成就写入。下面记录只提供可复核的场景和结果，不提交游戏资源、存档、反编译文件、个人路径或账号资料。

| 用例 | 结果 |
| --- | --- |
| 同一事故档连续三次 F9 读取 | 每次消费 `3/3` 事件，到达原选项等待点 |
| 恢复后 F5 再保存并读取 | `3/3` 完成，仍到达原选项 |
| 同场景父脚本进入子脚本后新保存 | 保留父入口，人物介绍、随机和骰子记录均保留；按原始脚本读取消费 `12/12` |
| 故意触发人物立绘异常 | 回放停止，输入与速度恢复；报告为 `INCOMPLETE`，手动及自动保存未改变副本 |
| 上述异常后 F9 重试 | `12/12` 完成，失败状态解除 |

共六轮成功读取均取得 `PASS`，每轮比较 3367 项状态，有效差异为零。沿用现有验证范围，时间戳与 `FreeRandomState` 仍按原规则排除。原账号目录的 40 个存档及相关文件在测试前后，文件清单、长度和 SHA256 均一致，并由外部脚本复核。已检查截图中的厨房、人物与站位。临时测试插件在验证后移除。

六轮实机覆盖核心恢复逻辑；后续代码审查补充了失败期间存档 postfix 的早退保护，避免原生写入被跳过后仍更新附加档，该早退由独立 CLR 回归验证。

## 范围限制

默认 45 秒无进度保护及暂停计时尚未单独进行实机超时测试。未覆盖全部剧情路线、全部历史旧档、菜单鼠标操作、语音进度或 UI 动画的精确位置。状态快照也不包含 Lua 局部变量、表和函数；`PASS` 不能扩展解释为这些状态完全一致。
