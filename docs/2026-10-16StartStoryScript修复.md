# 2026-10-16 剧情起点恢复修复

适用版本：游戏 `release_1.0.6000.2`，MOD 2.0.2。本页记录发布前的修复与验证。

## 问题与原因

004 槽报告只有一项有效差异：`Game.StartStoryScript` 保存时为 `ch1_1`，读取后为 `S0200_01`。实际运行剧情、对话停点及其余参与比较的状态一致。

原生 `PlayerStatManagerData.Load` 将存档的 `StartStoryScript` 用于设置当前运行剧情，却没有恢复 `_startStoryScript` 本身，原来的会话值因此残留。后续保存会再次写入这个错误值。这属于真实恢复缺失，该字段继续参与验证，没有加入忽略名单。

回放入口与原生存档起点是两个独立概念：脚本中途的自动存档可以改变原生起点，但精确回放仍须从所记录的脚本边界开始。此前 MOD 为切换回放入口直接改写边界存档的起点，也需要一并取消。

## 修复

- 原生读取完成后，根据实际加载的存档恢复 `StartStoryScript`。
- 仅在启动精确回放时，将当前运行剧情切换到记录的回放入口。
- 保留边界存档原有的起点与剧情字段；回放中的原生起点更新仍正常执行。
- 无附加档和内部恢复路径恢复各自存档的起点，不启动精确回放。
- 不修改附加档格式，不需要重新保存原 004 存档后才能读取。

## 验证结果

所有游戏内操作均使用独立存档副本和输入替身，原账号 32 个存档及关联文件的 SHA-256 在测试前后全部一致。

| 检查 | 结果 |
| --- | --- |
| 修复前复现 | 原 004 副本完整回放 71 个事件，但起点仍为 `S0200_01`，准确复现唯一差异 |
| 修复后重复读取 | 两次读取同一 004 副本，均比较 3330 个字段、0 项差异、`PASS`；起点和当前剧情均为 `ch1_1` |
| 不同起点与回放入口 | 构造边界起点 `back_001`、回放入口 `ch1_1` 的测试副本，两者分别正确保留；0 项差异 |
| 再次保存并读取 | 上述不同起点副本经 F5 保存、F9 读取后仍为 0 项差异；原生档和附加档均保留正确起点 |
| 原生与内部读取 | 无附加档的普通读取、直接内部恢复均还原各自起点，未误启动回放 |
| 自动检查 | 48 项通过、0 项失败；31 个补丁方法目标与注入参数通过 |
| 构建与运行 | 编译 0 警告、0 错误；游戏测试未出现异常；测试插件已移除 |

测试保留 `FreeRandomState` 排除规则，起点字段没有被排除。这里的 `PASS` 只覆盖参与比较的字段和已验证的回放样本，不代表所有跨版本剧情档均兼容。
