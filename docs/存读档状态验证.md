# 存读档状态验证

适用版本：LOMSave 2.0.0，剧情/歇息附加存档。验证只读当前状态，不会把保存时的数值写回游戏。

## 操作

1. 在对话或选项暂停时，通过游戏自带的存档界面选择槽位保存；也可在已有当前槽位后按 F5。两种方式都会记录验证基准。
2. 推进后通过游戏读档界面读取该档，或按 F9 读取系统当前槽位；两种方式都会触发精确回放与验证。
3. 等回放与自动验证完成，先不要继续对话或选择选项。
4. 查看 `BepInEx/plugins/LOMSave2/verification/latest.txt`。历史报告文件名包含时间和槽位，日志也记录实际路径。
5. 按 F8 可再次比较；继续游玩后按 F8，会如实显示后续产生的变化。

如果配置了 `Verification.ReportDirectory`，以配置目录为准。关闭 `Verification.AutoCheck` 后仍可手动 F8。

## 结果

| 结果 | 含义 |
| --- | --- |
| PASS | 参与比较的值一致，未检测到回放异常 |
| DIFF | 有差异，报告逐项列出字段及保存值/当前值 |
| INCOMPLETE | 回放提前结束、错位、无明确等待位置或未取得快照 |
| 没有验证基准 | 旧档未包含快照，不能自动证明这次恢复与原保存状态一致 |

目前实机报告仍有 `Game.FreeRandomState.s0..s3` 四项差异。这会影响后续随机流程，报告不能改判为完整 PASS。

## 比较范围

包含基础与最终属性、钱、命运点数、好感、角色启用状态、天赋、武学、装备、背包、商店、任务、事件标记、日期、随机状态、场景与跳转资料、嵌入还原数据、Lua 标量全局，以及脚本、对话/选项/等待位置和记录的音乐/环境音键。

保存时间戳不参与一致性判定，但报告记录变化；列表按项目标识对齐，单纯重排不会产生误报。

自由行动原生存档没有这份验证基准。UI 动画、语音位置和 Lua 局部变量、表、函数不在比较范围。PASS 也不能替代读档后状态界面、菜单和继续游玩的检查。

## 旧档与异常

- 格式 3 若没有命运面板记录，首次回放按原选择人工确认；完成后重新保存，再读即可自动回放。
- 无记录时不会依据验证快照猜测历史选择。没有补选就再次保存，不能恢复原选择。
- 命运起始值、项目或上限不匹配时停止自动回放并提示人工操作，验证标记为未完成。
- 格式 2、附加档损坏或配对不一致时回退原生存档，恢复点可能更早。
- 日志出现 `Say hash mismatch` 时不能视为兼容；当前仍可能按位置跳过对话，应保留证据并检查脚本差异。
- 游戏更新后先按 [兼容性检查清单](../游戏更新兼容性检查清单.md) 测试副本，保留旧存档。

快捷键失效时确认游戏有焦点、配置键位正确，并检查日志中的 `[Loms] Hotkeys ready`。菜单或状态异常同时查看 `Player.log` 和 BepInEx 日志。
